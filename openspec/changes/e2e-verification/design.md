# Design: e2e через настоящий путь вызова

## Стенд

Один прогон = один временный `HERMES_HOME` (каталог в `/tmp`, удаляется или сохраняется по
флагу). В нём:

```
<home>/config.yaml                      web.search_backend: router, extract_backend: router,
                                        keyless_rescue: false
<home>/.env                              ключи вендоров (копия из окружения прогона)
<home>/plugins/web-router/__init__.py    register(ctx) -> ctx.register_web_search_provider(...)
<home>/plugins/web-router/plugin.yaml    name: web-router, provides_web_providers: [router]
<home>/plugins/web-router/router -> ...  симлинк на пакет из репозитория
<home>/state/web-router/                 ledger.json + routes.jsonl, которые пишет плагин
```

Почему `HERMES_HOME`, а не правка живого конфига: Hermes читает конфиг на каждый вызов,
поэтому смена `web.search_backend` в живом профиле мгновенно переключает Telegram-бота на
экспериментальный бэкенд. Изолированный home даёт тот же код-путь и ноль риска.

Почему симлинк на пакет, а не копия: e2e должен проверять **тот** код, который лежит в
репозитории. Копия начала бы отставать от правок.

## Шаги прогона (каждый — отдельная запись в отчёте)

| # | Шаг | Что доказывает |
|---|---|---|
| 1 | `_ensure_plugins_loaded()` → `get_provider("router")` | плагин найден загрузчиком, имя бэкенда совпадает с конфигом |
| 2 | `web_search_tool(query, 3)` | весь путь: тул → реестр → провайдер → ступень → вендор; конверт `{success, data.web[]}` |
| 3 | `asyncio.run(web_extract_tool([url]))` | асинхронная ветка и повторная вытяжка через Jina |
| 4 | `routes.jsonl` и `ledger.json` под `<home>/state/web-router` | учёт пишется, изоляция держится |
| 5 | тот же вызов с пустыми ключами и `ROUTER_KEYLESS_LAST_RESORT=false` | честная деградация: `success: false` с причинами, без трейсбека |
| 6 | живой профиль не изменился | `~/.hermes/state/web-router` не появился/не вырос |

Шаг 5 запускается отдельным процессом с другим `HERMES_HOME`, чтобы не тащить в него ключи.

## Что считается доказательством

- Шаг 2: `success: true`, ≥1 результат, поле `data.backend` начинается с `router:`.
- Шаг 3: `results[0].content` непустой, длина ≥ `ROUTER_MIN_PAGE_CHARS`.
- Шаг 4: в `routes.jsonl` появилась строка с `capability=search` и `served_by` из реальных
  вендоров; в `ledger.json` у обслужившего вендора `used > 0` (или `source: api` для
  firecrawl, где остаток берётся у вендора).
- Шаг 5: код возврата инструмента — JSON с `success: false`, в тексте ошибки есть имена
  ступеней; процесса-падения нет.
- Общий код возврата прогона: 0 только если все шаги прошли.

## Почему отдельный маркер, а не `live`

`live` = «ходит в интернет». E2E дополнительно требует **установленного Hermes** и тратит
квоту другим способом (через тул-путь). Раздельные маркеры позволяют прогнать адаптеры
живьём, не поднимая стенд, и наоборот. Оба исключены из `pytest` по умолчанию.

## Отчёт

`e2e-report.json` рядом с репозиторием (путь печатается в конце):

```json
{"ok": true, "steps": [{"name": "search_tool", "ok": true, "detail": "3 results via router:exa",
                        "seconds": 1.4}], "home": "/tmp/...", "spent": {"search": 1, "extract": 1}}
```

Отчёт — не украшение: он единственная улика, что прогон был, и его можно приложить к
релизу/инциденту.

## Находки первого прогона (2026-11-22)

Стенд нашёл два дефекта, которые офлайн-уровни пропускали — это и есть доказательство, что
уровень нужен:

1. **Провайдер не наследовал `WebSearchProvider`.** Реестр Hermes отказал с сообщением
   `tried to register a web provider that does not inherit from WebSearchProvider` и
   промолчал в ответе агента. Плагин грузился «успешно» и регистрировал пустоту.
   Правка: базовый класс импортируется с откатом на `object` для автономных тестов.
2. **Порог «короткая страница = стена» был выставлен в 400 символов.** example.com — 156
   символов настоящего текста; цепь считала это блокировкой, парковала Jina на 60 секунд и
   тратила кредит Firecrawl на нормальную страницу. Правка: порог 40 (пустая оболочка),
   стены ловятся маркерами (`enable javascript`, `captcha`, …), а не длиной.
3. **`except Exception as exc` в адаптере Jina читал `exc.kind`** — не-сетевое исключение
   роняло адаптер вместо ответа «эта страница не вышла». Правка: `StageError` и прочие
   исключения обрабатываются раздельно.
